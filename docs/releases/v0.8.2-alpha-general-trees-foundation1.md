# NPCortex v0.8.2-alpha — Vanilla Trees Foundation 1 (EXPERIMENTAL)

Built on top of the **Agent Recovery Fix 2** full repository. This is **not** a finished "every tree, every biome" implementation.

## Changes

- `TreeSpecies`: immutable eight-species Vanilla 1.20.1 **overworld** log/foliage registry: oak (including natural azalea canopy), spruce, birch, jungle, acacia, dark oak, mangrove, cherry.
- `WholeTreeTracker`: bounded 26-neighbour log component recognition (branches/diagonals), recognizes plausible 1x1 roots and 2x2 4-root trunks for spruce, jungle and dark oak. Natural canopy and root-ground checks reject ambiguous structures. Tree/owner/chunk/height caps still apply. This is a conservative heuristic, **not proof that a player did not build the tree**.
- Generalizes server-side leaf obstruction checking to natural non-persistent species-matching leaves.
- Broadens recognized log commands and chat quantities, Java mining allowlist and backend tree observation limits. Existing ownership, reach, permissions, verification and inventory semantics remain.
- Keeps committed logs observable even when high above the NPC's local scan, without force-loading chunks or giving LLM absolute coordinates.
- Whole-tree completion requires task goal and bag verification; no auto-delivery to player.

## Known missing features (NOT WORKING YET)

- **No universal 3D path planning.** The existing `approach` is ground-navigation and can fail for high/hanging or obstructed branches. `climb` still uses the existing 6-block single-column pillar (or declines). The model cannot reliably complete every large acacia/cherry/mangrove/jungle/dark-oak tree.
- Very large connected trees and tree clusters may be rejected by strict bounds, deliberately. Some huge trees exceed the 80-call LLM budget. Component membership does not prove a natural tree; avoid experimenting near builds.
- Huge crimson and warped fungi in the Nether are **not** part of this tree registry: their stem, wart cap, shroomlight and root structure need a separate bounded classifier and harvest verifier. Big mushrooms and bamboo are also not covered by wood-log harvesting.
- Only recognized Vanilla 1.20.1 blocks, not arbitrary modded wood or datapack species.
- **Forge Build and in-game validation have not been run by the authoring environment.** Standalone tests are not enough to claim functional species harvesting.

## Next milestone: Tree Access Planner

Observe an obstacle graph (ground traversability, collision, reachable stands, height changes, verified scaffold anchors, drop pickup positions). The Qwen model selects actions by observable tool affordances, while Java handles jump physics, collision-safe navigation, temporary structures, inventory and cleanup. Do not add one hardcoded sequence for each tree type. Improve bounded multi-step skill execution to reduce per-log LLM calls and support horizontal branches with reversible platforms.

## Acceptance Test Matrix

1. Small oak and birch 1x1 trunk: detect, mine, pick up, confirm, no stray logs.
2. Spruce and jungle 2x2 trunk: either correctly recognize tree or reject without block edits. Does **not** require a completed tall tree in this initial foundation.
3. Acacia horizontal branches and cherry canopy: classify logs/foliage correctly; report blocked access truthfully instead of claiming completion.
4. Dark-oak and mangrove: detect connected logs and avoid removing unrelated structures; record limitation when root/canopy shape is ambiguous.
5. Challenge case: player-built log wall + persistent leaves must not be destroyed based on a false "natural" classification. The heuristic remains imperfect; **use an isolated test world**.
6. Cancel, cleanup, inventory, stale model decisions, budget caps: regression tests.
7. Real Forge Gradle `build` and Minecraft 1.20.1 world tests are mandatory before promoting universal wood harvesting.

## Commands

```mcfunction
/npcortex task gather minecraft:birch_log 1
/npcortex task gather minecraft:spruce_log 6
/npcortex task gather minecraft:acacia_log 1
/npcortex task status
```

Only one chosen wood type per bounded gather task; mixed-tree inventory goals are future work.
