# NPCortex v0.8.2-alpha — Atomic Brain Choice Fix 1

Base: **3D Ground Access Fix 1** full repository, **no Forge/Java changes**.

## Issue observed in live Minecraft

After successful scaffold climbing and mining (`scaffold=3`, `mined=13`),
Qwen proposed `mine(b2)` despite `b2` lacking the `mine` affordance. The
backend correctly rejected it with HTTP 502, pausing the task.

## Resolution

The previous Qwen structured schema had **independent** `tool` and `target`
enums, permitting an invalid cross-product such as `mine(b2)` when `b2` was
only available for `climb`. The new Qwen format is an **atomic enum** of
server-grounded, action-target pairs (e.g. `mine:b0`, `climb:b2`, `pickup`).

Qwen still chooses a feasible action itself. The backend translates that
single choice back to the unchanged `tool`/`target` response expected by Java,
then revalidates it under the same existing tool/affordance and budget rules.
No arbitrary commands, invented coordinates, or direct Java execution.

* No hidden retries. Exactly one Qwen inference per Java agent request.
* No changes to Forge mod, Task State persistence, Character Packs, SQLite,
  Safety checks, Inventory or World Mutation behavior.
* Legacy `{tool,target,reason}` provider responses remain accepted only when
  they pass the original strict validator (for local adapters and tests).
* If Ollama violates the new enum, Backend still rejects it safely and the
  Task can pause; this is a model-format reliability fix, **not a guarantee
  of universal tree completion**.
* Backend must be restarted for the patch to take effect.

## Install

Close Python Backend. Extract **Update Only** ZIP to a temporary directory,
then run its `scripts/install-atomic-brain-choices-v082.ps1`:

```powershell
$zip = "$env:USERPROFILE\Downloads\NPCortex_v0.8.2-alpha_AtomicBrainChoiceFix1_UpdateOnly.zip"
$extract = "$env:TEMP\NPCortexAtomicChoiceFix1"
Expand-Archive -LiteralPath $zip -DestinationPath $extract -Force
& "$extract\scripts\install-atomic-brain-choices-v082.ps1" -ProjectRoot "F:\AI\NPCortex"
```

Then run `./scripts/test-v082.ps1` in the project root and restart `./scripts/dev-backend.ps1`.
The Java/Forge mod is **unchanged**; no Forge rebuild is needed for this fix.
