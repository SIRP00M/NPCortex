# NPCortex v0.8.2-alpha — Build Fix 2

This is a **compile-compatibility hotfix** for public `v0.8.2-alpha`, building on **Build Fix 1**. No release-version increment or new AI behavior.

## Cause

`WorldBlockActions.blockingNaturalOakLeaf` now requires a `boolean creative` argument to apply the authorized player reach mode. The legacy `GatherTaskController` still called the old two-argument form at its leaf-clearing and target-locating call sites, causing two Java compilation errors.

## Change

Pass `owner.isCreative()` at **both** legacy call sites. The leaf obstruction checker remains server-controlled; this hotfix does not relax world-edit permissions or change Qwen's tool choices.

Added `backend/tests/test_java_leaf_api_v082.py`, a focused static regression test to catch these two call-site mismatches. It does **not** replace a real Forge Gradle build.

## Validation

- Run `python -m unittest discover -s backend/tests -v`
- Run `./scripts/test-v082.ps1`
- On the Windows workstation with JDK 17 and Forge dependencies: `./scripts/build-agentic-v085.ps1 -SkipTests`
- Minecraft in-game World Interaction and Whole-Tree behavior remain unverified until tested in Minecraft.

The existing `ModLoadingContext.get()` deprecation warnings are warnings and are not the cause of this build failure.
