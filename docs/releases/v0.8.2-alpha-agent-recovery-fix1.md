# NPCortex v0.8.2-alpha — Agent Recovery Fix 1 (experimental)

Incremental patch based exactly on the **BuildFix3 Full Repository**. This is
not a new major release or a new project. The patch addresses the manual
Minecraft observations: 4/1 logs stored but one still hanging and 5/5 stalls
on `wait`, and a tall branched tree with 15 logs remaining and repeated
`no safe visible standing location` on ground navigation.

## Changes (AI still chooses HOW)

- **Grounded wait eligibility:** waiting is not offered as a useful tool when
  the committed tree still has observed log targets or a drop is already in
  pickup range. Qwen still chooses between grounded available skills. The
  server's finite request/failure/stall budgets are unchanged.
- **Verified-root scaffold anchor:** before the first block of a verified
  natural Oak is mined, the server records its verified root, not merely
  the position of the log the model chose. `climb(bN)` subsequently uses
  this persistent root, even when the chosen `bN` is a lateral branch.
  It does not add teleportation, place arbitrary blocks, or bypass existing
  world-edit/owner checks. A climb still needs eligible scaffold material
  in the **NPC bag** and real safe placement geometry.
- **Bounded leaf-clearing skill:** one Qwen `clear_leaf(bN)` selection may
  remove up to **three** individually rechecked natural Oak leaves that
  actually obstruct that target; it stops when access is restored, no
  approved leaf remains, or an action is rejected. This is one reusable
  physical skill, NOT a Java rule that chooses leaf-clearing for Qwen.
- **Debugging:** `/npcortex task status` now includes `scaffoldMaterial=true/false`
  to distinguish a navigation problem from missing materials.

This patch does NOT guarantee an NPC can reach a tree taller than the
existing six-block scaffold cap, navigate arbitrary branches, handle every
colliding canopy geometry, infer a tree's genuine world-gen provenance,
or collect scaffold resources autonomously. Qwen must select meaningful
skills; the Minecraft server validates and may pause safely when impossible.
The requested log count remains a MINIMUM. The committed tree must finish,
all mined drops must be in the NPC bag, and temporary edits must be cleaned
before the server can confirm task completion.

## Install from Update Only

Stop Minecraft and backend. Extract the UpdateOnly ZIP to a temporary folder.
Run the included script from its extracted location (not from old project
scripts) with `-ProjectRoot "F:\AI\NPCortex"`. The installer checks the
published version and baseline SHA-256s, refuses unexpected local changes,
backs up affected originals under `.npcortex-backups`, and leaves character
packs, SQLite, Minecraft saves and configuration untouched.

```powershell
& "$env:TEMP\NPCortexRecoveryFix1\scripts\install-agent-recovery-v082.ps1" -ProjectRoot "F:\AI\NPCortex"
cd F:\AI\NPCortex
.\scripts\test-v082.ps1
.\scripts\build-agentic-v085.ps1 -SkipTests
```

Restart backend and Forge dev client. Cancel any old paused task and start a
new one, because old partial tasks do not contain the persisted root anchor:

```mcfunction
/npcortex task cancel
/npcortex task gather minecraft:oak_log 1
/npcortex task status
/npcortex inventory
```

For a tall tree, verify `scaffoldMaterial=true`. Compatible materials in the
NPC bag include dirt, cobblestone, stone, oak planks, or oak logs. **The
player's hotbar is NOT the NPC bag.** Observe the actual `chosen=` and `last=`
statuses before concluding that Qwen is or is not choosing `climb`.
