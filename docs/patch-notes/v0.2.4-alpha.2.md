# NPCortex v0.2.4-alpha.2 — Patch Notes

**Development preview · 26 October 2026 · not a stable release**

This patch improves local API security controls and how NPC state is cleaned up when certain operations fail or the Minecraft server stops. It continues the `v0.2.4` reliability milestone.

## What's changed

- **Opt-in protection for existing API routes.** Set `NPCORTEX_REQUIRE_TOKEN=1` on the Python backend to require the shared NPCortex local token for legacy chat, actor, dialogue, social and agent APIs. The default remains **off** for existing installations. `/health` remains public to local callers.
- **Forge sends local credentials when available.** The chat and C2 integration attempt to attach the shared local token. Existing third-party clients or test scripts may need updates when the option is enabled.
- **Safer recovery from failed NPC spawning.** Cleanup is tied to the exact attempted avatar/profile, reducing the chance of accidentally removing a replacement record.
- **Cleaner server shutdown path.** Removed a redundant motion-stop step while retaining cancellation reconciliation.
- **Additional regression coverage.** Added focused Python tests for the optional authentication mode and legacy API compatibility.

## Limits

This update does **not** enable automatic mining, block placement, item pickup, or fully autonomous world-changing jobs. Token authentication is designed for **localhost**, not exposing the backend to the public internet. Multiplayer, dedicated-server shutdown, actual spawn-failure injection and end-to-end Java token behavior still need scenario-specific verification.

Previously confirmed single-player G4 tests remain valid **only for the scenarios tested**; they are not a blanket certification for this patch.
