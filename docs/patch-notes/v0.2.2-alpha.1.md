# NPCortex `v0.2.2-alpha.1` — C+ Core Contracts, Ownership & Unified API

**Development milestone · 22 October 2026 · Minecraft Java 1.20.1 / Forge 47.4.10 · `main` target (not pushed)**

This milestone lays the **contract foundation** for a future generalized NPC action engine. It does not introduce new usable in-game commands or an autonomous C+ gameplay controller.

## What's new

- **Typed action contract v1:** canonical world, dimension, actor, goal, task, action and attempt identities, target kinds and expected outcomes, independent Java and Python validation.
- **Authority and verification rules:** explicit lifecycle transitions; actions cannot become `COMPLETED` merely because a model said so, and potentially mutating uncertain actions are not blindly replayed.
- **Modular ownership:** C1 continues to own Player movement, inventory and physics; C2 continues to own navigation and Follow; C+ is designed to orchestrate action coordination later without collapsing those modules.
- **Resource/FIFO design:** deterministic resource key order and queue-ticket contracts for later concurrency coordination; **not an active scheduler or resource lock implementation**.
- **Unified Command / Public API design:** proposals for `/npcortex spawn`, `/npcortex follow`, `/npcortex stop`, `/npcortex status` and operator `/npcortex debug ...`, with legacy C1/C2 mappings and permission boundaries. **Not registered in Minecraft yet.**
- **Developer contracts and tests:** Java `CPlusF0ContractsSelfTest`, backend `test_cplus_f0_contracts.py`, `scripts/test-cplus-f0-contracts.ps1`, Windows checklist and implementation report.

## Compatibility

Existing `/npcortex c1 ...` and `/npcortex c2 ...` commands, active C1 inventory and C2 navigation/follow, and current backend services are unchanged by the new contract classes. No SQLite schema migration, new world-interaction Skill executor, changed permissions, or new migration has been implemented. Legacy command mappings are a design document, not a routing migration.

## Validation and known limits

This packaged ZIP passed **71 isolated Java assertions**, **15 backend C-F0 tests** and **16 focused Python C2 tests** with Exit Code 0; the source implementation report also records earlier Follow Java regression checks. The project owner separately confirmed the scoped Windows C-F0 acceptance checklist (spawn, grounded/flying Follow, unfollow, navigation, transaction replay, Save/Rejoin and Forge Build/contract tests). These are not evidence that future live C+ commands or a generalized action runner work. Full MSPT and broad Forge compatibility remain unmeasured.

Future C-F1 (durable journal), C-F2 (world/permission adapter), C-F3 (live router and action engine), C-F4 (adapters), C-F5 (performance) and C-F6 (end-to-end gates) require separate approval.
