# NPCortex v0.2.4-alpha.1 — Patch Notes

**Development preview · 26 October 2026 · not a stable release**

This update builds on NPCortex's task tracking and movement previews with more reliable NPC movement coordination, explicit recovery behavior and tools for verifying changes safely.

## Highlights

- **Guarded movement tasks.** An operator can submit a bounded NPC movement request through the existing C2 navigation flow. Task identities, outcomes, cancellations and uncertain results are tracked explicitly. This is **not** a general autonomous task engine.
- **More dependable recovery.** Improved handling of interrupted backend requests and durable transport records. Uncertain actions remain on **HOLD** rather than silently restarting or claiming success.
- **Safer runtime boundaries.** Additional validation of local HTTP requests and selected Minecraft server-thread operations reduces classes of preventable failures.
- **Better developer verification.** Optional M03 in-game acceptance tooling and a single-command M04 offline test runner help developers collect repeatable evidence.
- **M04 work foundation.** Typed work-step records, read-only target previews and inventory unequip support prepare future interactions with Minecraft blocks and items.

## What this does **not** unlock

NPCortex cannot yet claim safe automatic mining, block placement or real item pickup through M04. A preview does not modify a block. Automatic multistep world mutation, dedicated-server lifecycle recovery and multiplayer certification are **not** completed by this update.

## Verification

The project owner confirmed four Windows single-player scenarios for the targeted G4 changes: C1 spawn/motion, save/rejoin, shutdown with an active C2 goal and Follow start/stop. These do not cover all server-thread entrypoints or all player/world configurations. Independent acceptance is still needed for current-package Forge build, M04 live world actions, multiplayer and performance.
