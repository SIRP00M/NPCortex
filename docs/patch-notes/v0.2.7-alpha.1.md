# NPCortex v0.2.7-alpha.1 — Patch Notes

**28 October 2026 · Experimental native interactions**  
Based on GitHub `main` `v0.2.6-alpha.3` (`b192549`).

## Interact with nearby blocks and dropped items

NPCs can now be asked to **break one block (Brk)** or **pick up a dropped item (Pck)** from the NPCortex Manager. Choose a target with **Preview**, then explicitly **Confirm**. The system checks owner permission, action conflicts and world state before acting. Timed mining and item transfer run through the Minecraft server, with the backend recording the operation and its outcome.

## Safer recovery and ownership

Native action claims prevent two NPCs from controlling the same target at once. The durable action ledger and typed verification receipts distinguish proven completion from uncertain outcomes. Ambiguous states are held for operator reconciliation instead of blindly repeating a potentially completed action.

## What this update does *not* do

Brk and Pck do not automatically navigate into range. Dropped items are not automatically sucked into nearby NPC inventories as part of normal movement. This is not general AI-initiated harvesting, and the tests do not prove crash-window exactly-once effects or all modded multiplayer behavior.

## Verification

The owner has reported successful single-player native breaking, explicit pickup and claim conflict checks. This public package also passed 53 static contract tests, 72 native backend tests, and 5 request-lifecycle tests locally. Forge GameTests and Windows gameplay evidence are distinct from this packaging validation. Full Linux CI (Python 3.11) still requires confirmation for the new commit.

## Repository cleanup

The old G5 `g5n02`–`g5n10` test helper files are no longer part of the supported datapack. GitHub tracked them in older commits; use the separate `NPCortex_GitHub_Cleanup.cmd` before committing so they are removed from the Git index too. This avoids the prior misleading G5 static-test failure. Source tests and active `g5a` lanes are retained.

## CI follow-up (same version)

The GitHub Actions backend suite now runs platform-specific tests on the appropriate runners: Ubuntu executes the Python backend regression suite, and Windows executes the Native Acceptance PowerShell safety tests. The test suite still checks refusal of unsafe actions and preservation of local evidence. This is a CI-only fix and does not change gameplay or the native action safety policy.
